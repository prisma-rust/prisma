# Slang toolchain + Bindless migration guide

This document records Prisma's introduction of the **Slang shader toolchain** and **Bindless (descriptor-indexing) texture table**, and the commands and file locations used to maintain them now.

> Background: initial changes were developed on Termux/aarch64, where `cargo check`/`cargo test -p prism-render` were all green, but official `slangc` is a glibc binary and cannot run natively on Termux. Therefore shader compilation (`.slang → .spv` + reflection JSON) is done on desktop/CI; `.spv` and generated Rust bindings are checked-in, after which mobile builds normally.

---

## I. Slang toolchain

### File layout
```
assets/shaders/slang/*.slang              # one file per module (common.slang provides shared types)
assets/shaders/compile.sh                 # slangc compile script (.spv + reflection JSON)
assets/shaders/reflection/*.json          # slangc output reflection JSON (checked-in, drives codegen)
assets/shaders/*.spv                      # slangc products (checked-in, include_bytes! into binary)
crates/xtask/                             # reflection JSON → Rust binding codegen (independent workspace)
crates/prism-render/src/shader_bindings/   # @generated: one .rs + mod.rs per shader module
```

After migration, original GLSL sources (`*.vert` / `*.frag`) have been deleted, `assets/shaders/` only retains their `.spv`.

### Binding convention (`[[vk::binding(binding, set)]]`)

Set allocation is based on `.slang` source (Rust side `shader_bindings` generated from same reflection, no drift):

| Set | Resource |
|-----|----------|
| 0 | frame UBO / materials / lights (skybox reuses IBL `envCube` here) |
| 1 | bindless texture table (merged sampler + SRV arrays) |
| 2 | IBL (env / irradiance / prefiltered) |
| 3 | shadow map |

Push constant structs are **not hand-written**: all come from `shader_bindings::<module>::*` (`#[repr(C)]`, field order consistent with Slang reflection). Since std140 implicit tail padding may not appear in reflection, `VkPushConstantRange` `size` is explicitly hardcoded when needed (e.g. 144), do not rely on `size_of`.

> ⚠️ combined image sampler: Slang uses `Sampler2D`/`SamplerCube` (not separated `Texture2D + SamplerState`), to match Rust side `COMBINED_IMAGE_SAMPLER` descriptor and original GLSL.

### Desktop/CI wrap-up steps
```bash
# 1) Install slang 2026.21+ (for your platform):
#    https://github.com/shader-slang/slang/releases
#    Extract to .local/tools/slang/ (only agreed location), compile.sh will use it automatically.
#    Termux/aarch64 cannot use official glibc version; do this step on desktop/CI.

# 2) Compile shader → .spv + reflection JSON
#    Needs slangc 2026.21 or newer (submitted reflection is generated by this version);
#    older versions are rejected by the script because they silently drop "version" / "combined" / "sizes" fields.
#    (SLANGC can be overridden; otherwise sequentially find .local/tools/slang/bin/slangc and PATH)
bash assets/shaders/compile.sh
#   Outputs assets/shaders/*.spv; reflection JSON first written to temp dir, then byte-compared against committed files.
#   If inconsistent, script fails and lists lines (does not overwrite repository files by default). After confirming schema change is intentional, use
#   bash assets/shaders/compile.sh --write-reflection
#   to adopt new files.

# 3) Regenerate Rust bindings from real reflection (output directory is entirely rewritten: one .rs + mod.rs per module)
cd crates/xtask
cargo run --bin shader-bindgen -- ../../assets/shaders/reflection ../../crates/prism-render/src/shader_bindings
cd ../..

# 4) Verify
cargo test -p prism-render
```

> `assets/shaders/reflection/*.json` are **real slangc outputs** and checked-in: machines without slangc (Termux / Android build machines) can also run codegen; desktop/CI recompile once and drift guard compares at the end (see CI section at end of document). Manually editing reflection JSON will fail there.
>
> They are generated by slangc `2026.21` (CI `SLANG_VERSION` and `compile.sh`'s `SLANGC_MIN_VERSION` are both pinned to it; if your machine version is outdated, install per script prompt, do not lower the check). `compile.sh` checks `slangc -version`, and fails when reflection doesn't match repository — so the local workaround of "only generating `.spv` in /tmp" is no longer needed, and you shouldn't manually change `-reflection-json` target.
>
> Similarly, `assets/shaders/*.spv` are checked-in (deterministic products, ~460 KB): **new worktree or new clone can build without slangc**. If you change `.slang`, re-run `bash assets/shaders/compile.sh` and submit new `.spv` together; CI shaders job recompiles and compares `assets/shaders/`, drift fails.

### Why xtask is an independent crate (not build.rs)
- `build.rs` runs on every `cargo build` → if it calls slangc, it forces slangc dependency → **mobile build crashes directly**.
  (`crates/prism-render/build.rs` only does check + "compile if slangc available" fallback, only emits hint when slangc missing.)
- xtask is in workspace `exclude` list, default `cargo check`/`build` **completely ignores it**, generated `shader_bindings/` checked-in.
- Run as: `cd crates/xtask && cargo run --bin shader-bindgen -- <reflection dir> <output dir>` (cannot use `cargo run -p xtask`, as it is excluded).

## II. Bindless (descriptor-indexing)

### Design
`BindlessTextureTable` in `crates/prism-render/src/bindless.rs`: a large descriptor set containing one **runtime-sized `COMBINED_IMAGE_SAMPLER` array**. Shader uses `u32` handle to index; material/texture switching no longer requires rebinding descriptor set.

Flags: `PARTIALLY_BOUND | UPDATE_AFTER_BIND | VARIABLE_DESCRIPTOR_COUNT`, combined with `runtime_descriptor_array` + `shader_sampled_image_array_non_uniform_indexing`.

### Current status
- `context.rs`: when `rt_caps.descriptor_indexing` is true, enables 5 descriptor-indexing sub-features (runtime array / partially bound / update-after-bind / variable count / non-uniform indexing).
- Texture table held by `RenderTextureManager` (`bindless()` / `bindless_mut()`), `ForwardPass` only borrows its set + layout (set 1); IBL cubemap and BRDF LUT registered into handles at startup / scene switch.
- **PBR already uses bindless**: `scene_frag.slang` samples from set 1 runtime array, push constant uses generated `PbrBindlessPushConstants` (96 bytes, plus one `env_handle: u32`), sampling via `NonUniformResourceIndex`.
- Old independent descriptor sets (`descriptor.rs`, `ibl.rs` cubemap set, `external_overlay.rs`) **all retained and usable**: they are for devices not supporting descriptor-indexing and other passes, not legacy code waiting to be deleted.
- Rollout order was "add table first, then switch pipeline" incremental refactor — at the time renderer was large, rewriting binding style wholesale without visual verification environment was too risky.

### Mobile notes
- Not all Android GPUs support full descriptor-indexing. `context.rs` only enables when `descriptor_indexing` cap is true; if device lacks sub-features like `UPDATE_AFTER_BIND`, fall back to existing independent descriptor set path (old path retained, naturally fallback), must verify on real device.
- `UPDATE_AFTER_BIND` has weaker support on some mobile drivers.

## III. Code generation and resource budget specification

### 1. Push Constant memory layout and explicit alignment padding

- **Strong-typed derivation**: all push-constant struct definitions must be automatically generated by `xtask shader-bindgen` reading `assets/shaders/reflection/*.json`, strictly prohibit hand-written `#[repr(C)]` mirrors.
- **std140 alignment hole explicit occupancy**: code generator forces each field positioned at reflection record's `offset`. Memory holes produced by std140 spec are explicitly generated as `_pad_<offset>: [u8; N]` fields, ensuring Rust's `size_of` and each field offset strictly match shader side byte-by-byte.
- **Type-safe conversion**: generated structs automatically derive `bytemuck::Pod` and `bytemuck::Zeroable`, upload uses `bytemuck::bytes_of(&push)`, strictly prohibit raw pointers and unchecked slice casts.
- **Code generator implementation principle**: `xtask shader_bindgen` uses standard `std::fmt` string formatting rather than `syn` / `quote`, to avoid introducing heavyweight proc-macro dependencies into xtask dependency tree, greatly speeding up toolchain build.

### 2. Shader resource budget and ratchet monitoring (budgets.json)

- `assets/shaders/budgets.json` records and locks resource upper limits for each shader module (samplers, sampled texture arrays, UBO, SSBO, acceleration structures, descriptor total count, push constant byte count).
- `crates/xtask/src/shader_budget.rs` (`shader-budget`) summarizes actual reflection usage and compares against budget table. Shader changes exceeding budget trigger build and PR failure.
- Budget table has ratchet property: only updated via `cargo run --bin shader-budget -- --write-budget` when architectural decision confirms resource expansion is needed, and quota changes explicitly reflected in PR review.

## CI (`.github/workflows/ci.yml`)
4 jobs:
1. **changes** — doc-only fast track: diff only in `docs/`, `*.md`, `LICENSE*`, `.gitignore`, remaining jobs skipped (skipped jobs still report Success, keeping required checks mergeable).
2. **lint** — `cargo fmt --all -- --check`; desktop crates `clippy --all-targets -- -D warnings` (`prism-ecs/render/engine/platform`); `xtask` is workspace-excluded, fmt + clippy separately.
3. **desktop** — `cargo build/test --locked -p prism-ecs -p prism-render -p prism-engine -p prism-platform`. `prism-app` needs NDK target, so not in this job.
4. **shaders** — slangc compiles `.spv` + reflection, `shader-bindgen` regenerates bindings from new reflection, **drift guard** (committed bindings not matching real reflection fails), uploads `spirv` / `slang-reflection-real` as artifact.

> No Android job: APK / `.so` produced by `scripts/build-android.ps1` on desktop (see `AGENTS.md` "Android packaging chain").
> `.spv` is checked-in and compiled into Rust via `include_bytes!`, so shaders job's drift guard is a hard guarantee — anyone changing `.slang` without recompiling and submitting `.spv` will fail CI directly.
